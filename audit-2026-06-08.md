# Audit portálu Master the Flow — 2026-06-08

## Bezpečnostní audit

### Shrnutí

Portál prošel komplexním pentestem. Celkem nalezeno **15 problémů**:

| Závažnost | Počet | Stav |
|-----------|-------|------|
| CRITICAL | 2 | Opraveno |
| HIGH | 4 | 3 opraveno, 1 částečně |
| MEDIUM | 5 | 1 opraveno, 4 jako TODO |
| LOW | 4 | 3 opraveno, 1 jako TODO |

Výchozí stav: **nedostatečný**. Celá autentizace stála na klientském SHA-256 hashu — triviálně obcházitelná. Po opravách je základní bezpečnostní vrstva funkční.

---

### Nálezy

#### CRITICAL

**CRITICAL-1 — Gate hash v plain textu v app.js (auth bypass)**

- Soubor: `app.js:2`
- Konstanta `GATE_HASH` obsahovala SHA-256 hash přístupového kódu přímo v klientském kódu. SHA-256 bez saltingu a stretchingu lze na GPU cracknout za minuty. Celá autentizace probíhala výhradně na klientu — server ji nijak neověřoval.
- Útočník stáhne `app.js`, extrahuje hash, spustí offline brute-force, vstoupí na portál bez znalosti kódu.
- **Stav: OPRAVENO.** Viz sekce Provedené opravy.

**CRITICAL-2 — Chybí rate limiting na všech API endpointech**

- Soubory: všechny `functions/api/*.js`
- `POST /api/vote`, `POST /api/track`, `POST /api/subscribe` šlo volat neomezeně rychle. IP-based deduplikace obcházitelná přes VPN/NAT. KV store lze zahltit tisíci write operacemi za sekundu.
- Flood `track` endpointu způsobí throttling celého KV namespace, flood `subscribe` zaplní KV `sub_*` záznamy.
- **Stav: OPRAVENO.** Viz sekce Provedené opravy.

---

#### HIGH

**HIGH-1 — CORS wildcard na analytických endpointech**

- Soubory: `top.js:12`, `top-cards.js:3-4`
- Endpointy vracely `Access-Control-Allow-Origin: *`. `vote.js` měl správnou whitelist logiku, ostatní ne. Útočník z libovolné domény mohl číst agregovaná data (počty otevření, čtení, sdílení).
- **Stav: OPRAVENO.**

**HIGH-2 — KV injection risk přes `id` parametr ve vote.js**

- Soubor: `vote.js:2`, řádky 34, 52, 83
- Regex `VOTE_ID_RE` byl správný, ale nestačil. Validní ID s prefixem jako `analytics:card` by přepsalo analytics klíče. Aktuálně regex `:` blokuje, ale tenká jednovrstvá obrana.
- **Stav: OPRAVENO.**

**HIGH-3 — Subscribe endpoint bez autentizace**

- Soubor: `subscribe.js:29-43`
- `POST /api/subscribe` nepožadoval žádný auth token. Subscription stuffing mohl zaplnit KV a zvýšit latenci push notifikací.
- **Stav: ČÁSTEČNĚ OPRAVENO.** Přidán rate limit 5 subscriptions/hodinu per IP. Plná auth (Bearer token) označena jako TODO — závisí na stabilizaci CRITICAL-1.

**HIGH-4 — Email provozovatele v plain textu v kódu**

- Soubor: `notify.js:2`
- `VAPID_SUBJECT = 'mailto:daniel@gamrot.cz'` hard-coded v kódu veřejného repozitáře. Email leakuje ve veřejném GitHubu.
- **Stav: OPRAVENO.**

---

#### MEDIUM

**MEDIUM-1 — CSP obsahuje `'unsafe-inline'` pro styly**

- Soubor: `_headers:7`
- `style-src 'self' 'unsafe-inline'` — otevírá CSS injection vektor pro CSS-based data exfiltration. Aktuálně není jasný vstupní vektor, ale je to zbytečné riziko pro statické styly.
- **Stav: TODO.** Fix: přesunout inline styly do `styles.css` a odstranit `'unsafe-inline'`.

**MEDIUM-2 — Neomezené zapisování do KV přes track endpoint**

- Soubor: `track.js:53-120`
- Každý `card_read` event způsobí 2-4 KV write operace. Bez rate limitingu jde o přímý útok na KV kvótu.
- **Stav: OPRAVENO** (zahrnut v CRITICAL-2 rate limiting implementaci).

**MEDIUM-3 — Service worker cachuje data bez integrity ověření**

- Soubor: `sw.js:20-43`
- Archive JSON soubory ukládány do cache bez kontroly integrity. Cache poisoning by mohl vložit upravený obsah.
- **Stav: TODO.** Vyžaduje infrastrukturní změnu (podpis JSON payloadu). Dopad je spíše dezinformační.

**MEDIUM-4 — Chybí validace `Content-Type` na POST endpointech**

- Soubory: `vote.js`, `track.js`, `subscribe.js`
- `request.json()` voláno bez předchozí kontroly `Content-Type`. Parsing exceptions tiše swallowany.
- **Stav: OPRAVENO.**

**MEDIUM-5 — VAPID public key v klientském kódu**

- Soubory: `app.js:4`, `notify.js:3`
- Duplicitní definice VAPID public key. Inherentní omezení Web Push (klient key potřebuje), ale server nepotřebuje ji definovat znovu.
- **Stav: ČÁSTEČNĚ OPRAVENO.** Duplicita v `notify.js` odstraněna, server čte z env. Klient musí key znát — to je inherentní omezení standardu.

---

#### LOW

**LOW-1 — Insights CORS wildcard pro admin endpoint**

- Soubor: `insights.js:3-8`
- Admin endpoint `/api/insights` vracel `Access-Control-Allow-Origin: *` i přes ochranu `x-admin-secret`. Ochrana dostatečná, ale wildcard zbytečný.
- **Stav: OPRAVENO.**

**LOW-2 — Gate auth uložena v localStorage**

- Soubor: `app.js:22`
- `localStorage` přístupný jakémukoliv JS na doméně. Pokud by existoval XSS, útočník přečte session data.
- **Stav: TODO.** Vyřeší se při přechodu na HttpOnly cookie po stabilizaci CRITICAL-1.

**LOW-3 — Chybí X-Robots-Tag header**

- Soubor: `_headers`
- Portál bez `noindex` byl indexovatelný Googlem, přestože je určen jen pro členy.
- **Stav: OPRAVENO.**

**LOW-4 — community.js CORS fallback na `*` místo zamítnutí**

- Soubor: `community.js:5-8`
- Neznámé originy dostávaly `'*'` místo `'null'`. Nekonzistentní s ostatními endpointy.
- **Stav: OPRAVENO.**

### Provedené opravy

**CRITICAL-1 — Server-side autentizace**

`app.js`: Odstraněn `GATE_HASH`, `GATE_TTL`, funkce `sha256`. `tryUnlock()` nyní volá `POST /api/auth`, klient ukládá HMAC session token.

`functions/api/auth.js`: Nový endpoint. Přijme kód, porovná s `env.GATE_CODE` (constant-time comparison), vrátí HMAC token. Rate limit 10 pokusů / 15 minut per IP.

**Nutná akce po deployi:** Nastavit env proměnnou `GATE_CODE` v Cloudflare Pages. Stávající uživatelé budou při příštím přístupu vyzváni k opětovnému zadání kódu.

---

**CRITICAL-2 — Rate limiting**

Implementováno na všechny endpointy:

- `/api/auth`: 10 pokusů / 15 minut per IP
- `/api/vote`: 20 akcí / 60 sekund per IP
- `/api/subscribe`: 5 subscriptions / hodinu per IP
- `/api/track`: 1 request / 5 sekund per IP (silent drop)

---

**HIGH-1 — CORS sjednocení**

`top.js` a `top-cards.js` přepsány na `corsHeaders(origin)` vzor identický s `vote.js`. Whitelist: `SITE_ORIGIN` + `localhost`, ostatní vrátí `'null'`.

---

**HIGH-2 — KV injection ochrana**

`vote.js`: Přidána funkce `isSafeVoteId()` s negativní kontrolou rezervovaných prefixů (`analytics`, `sub_`, `community_`, `voted_`, `vote_`).

---

**HIGH-4 — Email z kódu do env**

`notify.js`: Odstraněny hard-coded `VAPID_SUBJECT` a `VAPID_PUB_B64`. Server čte `env.VAPID_SUBJECT` a `env.VAPID_PUBLIC`.

**Nutná akce po deployi:** Nastavit `VAPID_SUBJECT=mailto:daniel@gamrot.cz` a `VAPID_PUBLIC=<existující hodnota z app.js>` v Cloudflare Pages env.

---

**Ostatní opravené:** LOW-1 (insights CORS), LOW-3 (X-Robots-Tag), LOW-4 (community.js CORS), MEDIUM-4 (Content-Type validace).

## Nápady na rozvoj komunity

### Prioritní funkce (high value, low/med effort)

**1. Reading streak + badge**

Počítá po sobě jdoucí dny otevření portálu. Po 7, 30 a 100 dnech vizuální badge. Streak counter v hlavičce.

Proč: Nejsilnější retention mechanismus. Lidé se vrátí jen kvůli streaku (Duolingo, GitHub).

Tech: KV klíč `streak:{userId}` s `{lastDate, count}`. Aktualizace při page load. Badge v localStorage.

---

**2. Push notifikace s konkrétním obsahem**

Každý den ráno (8:00) push s textem z dnešní nejlépe hodnocené karty — ne generické „Nový obsah", ale skutečný tip. Klik otevře přímo tu kartu.

Proč: Push s generickým textem ignorují všichni. S konkrétní hodnotou v preview je CTR 3-5x vyšší.

Tech: Worker Cron Trigger. Kód pro Web Push API už existuje — jen změna obsahu zprávy a výběr karty s nejvyšším score.

---

**3. Uložené karty (záložky)**

Třetí akce v UI (vedle hlasování) — „Uložit pro pozdějí". Vlastní sekce `/saved` se všemi uloženými kartami.

Proč: Aktuální srdíčko je hlas, ne reminder. Toto řeší jiný use case: „přečtu to, až budu mít čas."

Tech: KV klíč `bookmarks:{userId}` jako pole card ID. Nová route. Pokud není cross-device sync, localStorage stačí pro MVP.

---

**4. Týdenní e-mail s top kartami**

Každou neděli automatický e-mail „5 nejlepších insightů týdne" — top 5 karet podle weighted score. HTML šablona s přímými linky na karty.

Proč: Lidi neotevírají portál denně ale nechtějí miss out. Email je druhá šance.

Tech: Worker Cron (nedělní ráno) + Cloudflare Email Workers. Opt-in přes nastavení. Šablona staticky v Worker kódu.

---

**5. „Vyzkoušel/a jsem to" reakce**

Druhé tlačítko pod kartou vedle srdíčka. Counter ukazuje kolik lidí to reálně zkusilo — odlišuje engagement od akce.

Proč: „47 lidí to vyzkoušelo" je silnější než 47 srdíček. Social proof zaměřený na chování.

Tech: Druhý KV counter `tried:{cardId}`. Nová ikona (checkmark) v overlay. Minimální změna datové struktury.

---

### Další nápady

**6. Osobní heatmap aktivity (MED value / LOW effort)**

GitHub-style activity calendar pro konkrétního uživatele — kolik karet přečetl/hlasoval každý den. Synergicky s reading streak (body 1 + 6 sdílí KV data).

**7. Onboarding pro nové členy (MED value / LOW effort)**

Nový uživatel (nulové reads) dostane banner „Začni tady" s 5-7 kurátorovanými kartami. Skryje se po přečtení X karet. Seznam konfiguruje Daniel nebo automaticky z all-time top.

**8. Personalizovaný feed podle zájmů (HIGH value / MED effort)**

Při prvním vstupu výběr 2-3 kategorií. Feed řadí karty s preferovanými kategoriemi nahoru. Portál má 400+ členů s různou úrovní (Curious vs. Builder vs. Expert) — jeden feed pro všechny je suboptimální. Vyžaduje tagy na kartách.

**9. Komunitní leaderboard (MED value / MED effort)**

Anonymní žebříček top 10 čtenářů/voličů za poslední týden. Opt-in. Anonymizace — první 3 písmena + hvězdičky.

**10. Editor's picks — Danielův výběr týdne (MED value / MED effort)**

Daniel ručně označí 3-5 karet jako „Týdenní výběr". Speciální badge, samostatná sekce na homepage. Admin endpoint chráněný Worker route.

**11. Cross-device sync (MED value / MED effort)**

Záložky, přečtené karty a hlasy synchronizované mezi zařízeními. Nyní localStorage = ztráta dat při přepnutí na telefon. Vyžaduje auth layer (anon token nebo magic link).

**12. Milestone bannery (LOW value / LOW effort)**

Dočasný banner nebo push při komunitním milestonu (500 hlasů, 1000 přečtených karet). Jednorázový flag v KV aby se neopakoval.

**13. Tematické clustery „Přečti si víc" (MED value / HIGH effort)**

Pod kartou odkaz na 3-5 karet ze stejné série. Lepší content discovery než random surfování. Vyžaduje tématické tagy na kartách a backfill existujících dat.

## Doporučené další kroky

**1. Deploy a nastavit env proměnné (ihned)**

Po deployi oprav nastavit v Cloudflare Pages Dashboard: `GATE_CODE`, `VAPID_SUBJECT`, `VAPID_PUBLIC`. Bez toho auth a push notifikace nefungují. Komunikovat stávajícím uživatelům, že budou muset kód zadat znovu.

**2. Dokončit HIGH-3 (subscribe auth)**

Přidat ověření `Authorization: Bearer <token>` na `subscribe.js` a `unsubscribe`. Závisí na stabilizaci CRITICAL-1 — teprve po ověření že server-side auth funguje správně v produkci.

**3. Opravit MEDIUM-1 (CSP unsafe-inline)**

Přesunout inline styly do `styles.css`, odstranit `'unsafe-inline'` z `style-src` v `_headers`. Jednoduchá změna, eliminuje celou třídu CSS injection útoků.

**4. Implementovat reading streak + push s obsahem (body 1 a 2 z nápadů)**

Nejlepší poměr value/effort z celého seznamu. Dají se implementovat za 1-2 dny. Streaky a obsahový push přinesou měřitelný nárůst denní návratnosti bez nutnosti větší architektury.

**5. Naplánovat MVP záložek a týdenního emailu (Q3 2026)**

Uložené karty (bod 3) a týdenní email (bod 4) jsou klíčové pro long-term retention. Záložky vyžadují rozhodnutí: localStorage (rychle, bez cross-device) nebo KV s auth (správně, ale víc práce). Doporučení: localStorage MVP jako první iterace.
